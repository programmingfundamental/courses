## Самостоятелни задачи


### Задача 1 — Проверка на claims и ключове

В Postman проверете грешен подпис, изменен payload, изтекъл token, изключен user и валидна сесия без Bearer. За друг iss/aud, липсващи exp/sub и празен sub използвайте локално подготвени от преподавателя tokens, подписани с учебния ключ; не изпращайте ключа към външни услуги. Ако такъв token липсва, отбележете случая като неизпълнен. Точната граница на exp се доказва с контролиран часовник в упражнение 11. Валидният token работи; USER token към admin-only ресурс получава 403. Проверете aud като списък.

### Задача 2 — Еднократен refresh token

Променете refresh така, че старият token да се използва веднъж и да се замени с нов. Пазете SHA-256 digest в DB; raw token се връща само при издаване. Refresh и revoke са транзакционни, с атомарна употреба на token. В Postman изпратете два последователни refresh опита със старата стойност: един успех и един отказ. Проверете изтекъл token, disabled user, повторна употреба и logout. Последователните заявки не доказват поведение при конкуренция; тази проверка се автоматизира в упражнение 11. Опишете валидността на вече издадения access token след logout.
