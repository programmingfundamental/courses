# Практическо контролно по уеб сигурност — вариант 2

Изследвайте cookies, валидацията на пароли, текущия профил, собствеността и изтриването в учебния Task Manager. За всяка от петте проверки обосновете отговора си с действителни заявки, отговори и състояние на данните.

## Стартиране на готовия пакет

Нужна е Java 17 или по-нова. Разархивирайте целия пакет в отделна папка, стартирайте `start.cmd` и отворете [лабораторията](http://127.0.0.1:9011). В Linux/macOS използвайте `sh start.sh`. За готовия пакет не са необходими Maven, Docker или интернет.

## Стартиране от изходния проект

Нужен е JDK 17 или по-нов. От тази директория в PowerShell:

```powershell
java -version
.\mvnw.cmd clean verify
java -jar target/web-security-assessment-variant2.jar
```

В Linux/macOS заменете Maven командата с `sh ./mvnw clean verify`. Първото изграждане изтегля Maven и зависимостите и изисква интернет. Отворете http://127.0.0.1:9011. Ако портът е зает, добавете `--server.port=9012` към Java командата и отворете новия порт. Спиране: Ctrl+C.

H2 се стартира с приложението и записва в `data/assessment-variant2.mv.db` спрямо текущата директория. Продължавайте от същата папка и браузърен профил. Не изтривайте cookies или папката `data` преди предаването.

## Стартиране с Docker

```powershell
docker compose up -d --build --wait
```

Използвайте http://127.0.0.1:9011. `docker compose down` спира приложението и запазва тома с данните. При зает порт задайте `$env:ASSESSMENT_PORT='9012'` преди стартиране. Първото изграждане изисква интернет.

## Подготовка

Прочетете „Подготовка“ в сайта и изпълнете решената примерна проверка. Работете в един раздел. Всяка проверка има отделни копия на следните профили:

| Потребител | Учебна парола | Роля |
| --- | --- | --- |
| alice | Alice-lab-2026! | USER |
| bob | Bob-lab-2026! | USER |
| admin | Admin-lab-2026! | ADMIN |

Alice притежава 101 и 102, Bob — 201. Задача 101 има отчет 501. Бутонът с име попълва профила; натиснете „Вход“, за да изпратите заявката. Панелът използва session cookie и не добавя Authorization header. В дневника наличието на такива удостоверителни данни се отчита с булеви полета, а стойностите на пароли, cookies, tokens и хешове са скрити.

## Самостоятелни задачи

1. Заявка без Authorization и запазена сесия.
2. Символи, UTF-8 байтове и регистрация.
3. Кой определя върнатия профил?
4. Собственик при създаване и редактиране.
5. Изтриване, собственост и свързан отчет.

Всяка проверка в сайта съдържа условия, стъпки, шаблони за реални HTTP заявки и въпрос. „Начални данни“ възстановява само текущата проверка; отговорът и дневникът се запазват с номерата на опитите. За новите задачи използвайте действителния ID от отговора.

## Предаване

Запишете за всяка проверка действие → наблюдаван резултат → извод и номерата на доказателствата. Изчакайте „Запазено“. В „Протокол“ попълнете име и факултетен номер, натиснете „Подготви протокола“, после „Изтегли готовия JSON файл“. Името на файла съдържа `variant2`, а вътре е записано `variant: 2`.

Прикачете JSON файла към асаймънта в Teams и завършете предаването преди крайния срок. Изтеглянето не изпраща файла автоматично. PDF чрез „Печат“ е допълнение, а не заместител на JSON. Не записвайте пароли, cookies или tokens в отговорите. Броят попълнени отговори не е оценка за правилност.
