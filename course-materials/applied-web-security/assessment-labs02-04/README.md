# Практическо контролно по уеб сигурност

Изследвайте регистрацията, входа, сесиите и правата в учебния Task Manager чрез пет практически проверки. Изпращайте заявки от браузъра, наблюдавайте отговорите и състоянието на данните и обосновете изводите си с дневника на проверките.

## Стартиране с Java

Нужен е JDK 17 или по-нов; включеният Maven Wrapper изтегля Maven и зависимостите при първото изграждане. Не са необходими Node.js, npm, PostgreSQL или отделно инсталиране на H2.

От тази директория в PowerShell:

```powershell
java -version
.\mvnw.cmd clean verify
java -jar target/web-security-assessment.jar
```

В Linux или macOS:

```bash
java -version
sh ./mvnw clean verify
java -jar target/web-security-assessment.jar
```

Отворете [лабораторията](http://127.0.0.1:9010). Спрете сървъра с Ctrl+C. Ако портът е зает, стартирайте с `java -jar target/web-security-assessment.jar --server.port=9011` и отворете съответния адрес.

H2 записва данните във файл `data/assessment.mv.db` спрямо директорията, от която стартирате приложението. Използвайте същата директория и същия браузърен профил, за да продължите работата си след рестарт. Не изтривайте cookies, преди да изтеглите протокола.

## Стартиране с Docker

```powershell
docker compose up -d --build --wait
```

Отворете [лабораторията](http://127.0.0.1:9010). `docker compose down` спира приложението и запазва данните в тома. Първото изграждане изисква интернет. Ако портът е зает, задайте `$env:ASSESSMENT_PORT='9011'` преди командата и използвайте порт 9011 в браузъра.

## Подготовка

Отворете страницата **Подготовка** в приложението. Тя съдържа решен пример за прочитане на собствена задача и проверка на резултата. Всяка от петте проверки има отделни копия на следните профили и данни:

| Потребител | Учебна парола | Роля | Задачи |
| --- | --- | --- | --- |
| alice | Alice-lab-2026! | USER | 101 и 102 |
| bob | Bob-lab-2026! | USER | 201 |
| admin | Admin-lab-2026! | ADMIN | — |

Към задача 101 има отчет 501. Използвайте само тези учебни данни и приложението за контролното. Избраният профил се попълва във формата, но трябва да натиснете **Вход**, за да изпратите заявката. При проверка за смяна на потребителя запазете съществуващата сесия, както е описано в заданието.

## Задачи и протокол

В **Лаборатория** отворете последователно:

1. Роля при регистрация.
2. Повторен опит за вход.
3. Смяна на потребителя и сесията.
4. Отказ и състояние на данните.
5. Собственост и административни права.

Всяка проверка има входни условия, действия и въпрос. Панелът изпраща реални HTTP заявки към Java сървъра. Дневникът съдържа статуса, тялото на заявката и отговора, самоличността и обозначението на сесията. Cookie се изпраща автоматично; панелът не добавя Bearer token. Паролите и стойностите на tokens са скрити в дневника.

**Начални данни** възстановява само текущата проверка. Запазва отговора и дневника, като следващите записи получават нов номер на опита. Отварянето на проверка изпраща заявка за текущата сесия; тя също присъства в дневника.

За всяка проверка предайте действие → наблюдаван резултат → извод и посочете номерата на доказателствата. В **Протокол** попълнете име или факултетен номер, прегледайте отговорите и изберете **Подготви протокола**, после **Изтегли готовия JSON файл**. Предайте JSON файла по указания начин; изтеглянето не го изпраща автоматично. Непопълнените отговори остават видими в прегледа. По желание използвайте и **Печат** за PDF чрез браузъра.

Сайтът запазва отговорите на сървъра. Изчакайте индикатора **Запазено**, преди да затворите страницата. При прекъсване на връзката запазете въведения текст и повторете изтеглянето, след като сървърът е достъпен.
